# Life book ("Lebensbuch")

A standalone chronicle of the logbook that stays readable without TravStats for decades:
ONE offline HTML file for a year, a trip or everything.

## Contract

- `POST /api/v1/me/life-book` `{ scope: "all" | "year" | "trip", year?, tripId?, lang: "de"|"en" }`
  -> `202 { jobId }` (job kind `lifeBook.export`, progress = trips done / trips total).
  Own account only: a foreign `tripId` is 404 `TRIP_NOT_FOUND`. One run per account (409 `LIFE_BOOK_BUSY`).
  No entries in scope: job fails `LIFE_BOOK_EMPTY`.
- `GET /api/v1/me/life-book/:exportId` downloads the finished `.html` (owner only, TTL 6 h).
- Size limit `LIFE_BOOK_MAX_BYTES` (default 100 MB): over it the job fails `LIFE_BOOK_TOO_LARGE`,
  and the UI tells the user to narrow the scope (a year or one trip).
- The book text follows `lang` (the web UI language; accounts have no language column).

## The file

- Inline CSS, no `<script>`, no external request (`http(s)://` appears only as plain text, never as
  `src`/`href`/`url()`), images as `data:` URIs. `@media print`: A4, a page break per trip.
- Per trip: header (dates, countries with flag emoji + localized name, travellers = account + companions,
  trip notes), a route map, a chronological day list, then "date unknown".
- Day list: flights, rail, bus, ferry, rental, cruises, stays, place visits, journal entries.
  An entry with no date goes to "Date unknown" - never a guessed day. A day is the LOCAL day of the entry's zone.
- Per entry its evidence line "Beleg: Buchung, Bordkarte" from `DocumentLink` kinds (kind labels only,
  never file names). Trip-level documents are listed in the header.
- Entries without a trip form a closing chapter ("Without a trip") in the `all` and `year` scopes.

## Map

No tiles (offline, no external request, nothing to cache for decades): the map is an inline SVG
of the trip's coordinates (equirectangular, cosine-corrected), legs as lines, points numbered with a
legend list of places and coordinates. It says so. No coordinates: no map, the list stays.

## Photos

Capped: trip photos (12 per trip, by `sortIdx`) and place-visit photos (3 per visit, manual before
auto), 24 per trip at most. Disk copies are decoded (JPEG/PNG; HEIC via its display copy) and
box-filtered to at most 900 px, re-encoded JPEG. Photos only linked from Immich/PhotoPrism are fetched
server-side with the owner's own connection (the same `createPhotoSource` + egress rules as the asset
proxy; the row is the grant) as their "preview" rendition and embedded as delivered. A photo that
cannot be read is left out and counted in the result (`photosSkipped`), never silently. Album-linked
photos that are no `TripPhoto` row are not selected.

## Not in scope

Live data (weather, prices), expenses, other accounts' data, stops/tours, PDF generation
(the browser prints it).
