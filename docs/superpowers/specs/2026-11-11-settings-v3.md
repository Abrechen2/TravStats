## Ground rules

1. **The registry stays the single list.** `frontend/src/pages/Settings/registry/data/*.ts`
   is generated by `frontend/scripts/generate-settings-registry.mjs`. Phase S1
   points the generator at a new source, `docs/superpowers/specs/2026-11-11-settings-v3/settings-data.json`,
   written from `prototype-pages.js`; every later phase edits that JSON and
   regenerates. Search, menu and pages read the registry — no hand-kept second list.
2. **No setting is lost silently.** A row the prototype drops is either a fixed
   default now (Part A says which value) or removed with its column in a
   migration that keeps the stored value readable for export. Each removal is
   named in the phase report.
3. **Domain gating** as everywhere: a domain page or row shows only while that
   domain is on (`useEnabledDomains()`), never an empty page.
4. **Copy:** German first, English mirror in the same change (`localeKeyParity`).
5. **Touch:** sizes follow `useCoarsePointer`; iPad 1366 and 820 are the check sizes.
6. **Additive API only** (the Companion reads settings too); a removed field
   stays readable until the plan names the app version that stops using it.

Kept, with the reason:

- `fstatus`, `r_poi`, `bahnkontakt`: coordinator calls in this document.
- `linkserlaubt`: the prototype has it (`links`, Funktionen > Teilen); S3 parked a copy, S5 moved it, nothing was left to remove.
- `listen` on Daten is the heading of the list-import tiles, not a link; it stays.
- `immnacht` (nightly photo scan), `immvisit`, `dawsweep`, `logorefresh`, `ollpull`: a choice with a cost or a one-off job with no other trigger. Removing them would take the feature away, not a setting.
- `aerotracks` (real flight paths after landing): spends the admin's paid AeroAPI quota, so "on when the key is entered" is not a safe default.
- `fedtrips`: the beta gate `federatedTripSharing` decides, the row is the only switch.
- `openData` (card + `openDataEnabled`): off by default on purpose (each call sends a place and a date); only gated by the master switch.

Migration `20261111200000_settings_v3_s6_removals`: drops 11 `admin_settings` columns. Data moves in one case: an install that had switched all five outbound switches off gets `internet_enabled = false` (replayed by `migration.settingsV3S6.test.ts`); any other combination falls to the default (on).

Behaviour that changes for an existing install: automatic backups run even where `backup_enabled` was off (default was off); a verbose log period now writes the HTTP, database and parser files; a partly-off combination of the five outbound switches reads as on.

Links: about 40 in-app links used old `/settings/<page>` and `/admin` forms and now name the page ids; `noOldLocationLinks.test.ts` fails on any new one. Redirects stay for bookmarks.

Found, out of scope: the OpenSky resolver still builds basic-auth credentials from stored legacy values, which the service rejects; the admin backup retention still reads env `BACKUP_RETENTION_DAYS` before the column (Part A.3); `FieldsGroup`'s `dependencyOf` prop has one user left (`ServerOwn`).
