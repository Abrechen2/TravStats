# Passkeys (WebAuthn) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user optionally register one or more passkeys and sign in with one instead of typing a password.

**Architecture:** A passkey replaces the password rather than adding a step to it — the authenticator already proves possession of a device plus a local gesture, so treating it as a second factor on top of a password would be theatre. Registration happens inside an authenticated session; sign-in is its own two-call flow (`options` then `verify`) that ends with the same JWT cookie every other login produces. Credentials live in their own table, one row per device, each with a signature counter and a friendly name so a user can revoke the laptop without losing the phone.

**Tech Stack:** `@simplewebauthn/server` on the backend, `@simplewebauthn/browser` on the frontend, Prisma/Postgres, Jest and Vitest.

## Global Constraints

- **Opt-in per user. There is no way to require it.** Password login keeps working for everyone, including users who registered a passkey — a passkey is an additional way in, never the only one.
- Code, comments and commits in English. UI copy German first, English mirrored in the same change.
- `any` is forbidden — `unknown` plus type guards.
- Zod for every request body, schemas under `backend/src/schemas/`.
- `authLimiter` on every endpoint in this feature.
- Migrations via `npx prisma migrate dev` against a worktree-local database, never the shared `flights_dev`.

## The constraint that shapes everything: origin binding

A WebAuthn credential is bound to an **RP ID** — a domain — and the browser refuses to use it anywhere else. This is not a setting we can loosen; it is what makes the standard phishing-resistant.

TravStats is routinely reached under **more than one origin**. The instance model says so itself: `backend/src/services/instanceSettingsService.ts:69-70` carries both `publicUrl` and `lanUrl`. A passkey registered at `https://trav.example.com` **will not work** at `http://<prod-host>:3010`, and no code in this repository can change that.

Three consequences, all of which this plan handles rather than hides:

1. **The RP ID must be configured explicitly**, not guessed from whichever `Host` header arrived. Guessing produces credentials that silently stop working when the user switches from LAN to tunnel. Task 1 makes it an instance setting with a clear label.
2. **`localhost` is exempt** from the secure-context rule, but a bare LAN IP over plain HTTP is not: browsers refuse WebAuthn there outright. An instance reachable only as `http://192.168.x.x:3010` cannot use passkeys at all. Task 1 detects that and says so in the UI instead of offering a button that fails.
3. **A credential is scoped to an RP ID, not to a full origin.** That distinction matters and an earlier draft of this plan got it wrong: one passkey registered under the RP ID `example.com` works across `app.example.com` and `www.example.com`, because an RP ID may be a registrable parent domain. What it can *never* span is unrelated names — and a bare IP address is not a valid RP ID at all. So for this app's real situation, `trav.example.com` versus `<prod-host>:3010`, there is no shared RP ID available and the user genuinely needs one credential per reachable name. The list in Task 6 shows each key's **RP ID** (labelled as such, not as "origin") so the situation is legible rather than mysterious.

`@simplewebauthn/server` accepts an ARRAY for `expectedOrigin` and `expectedRPID`. Task 1 therefore stores a list, not a single value — otherwise the plan would tell a multi-origin story that its own implementation could not honour.

```typescript
import { prisma } from "../../db";

export interface RpConfig {
  rpId: string;
  origin: string;
  rpName: string;
}

export type PasskeyUnavailableReason = "notConfigured" | "insecureOrigin";

const LOCAL_HOSTS = new Set(["localhost", "127.0.0.1", "::1"]);

/**
 * Why passkeys cannot be offered for this origin, or null when they can.
 *
 * WebAuthn requires a secure context. Browsers make one exception —
 * localhost — so a developer can work over plain http. A LAN IP or a .local
 * name over http is NOT exempt: the browser rejects the ceremony outright, and
 * a button that always fails is worse than an honest explanation.
 */
export function passkeyUnavailableReason(url: string | null): PasskeyUnavailableReason | null {
  if (!url) return "notConfigured";
  let parsed: URL;
  try {
    parsed = new URL(url);
  } catch {
    return "notConfigured";
  }
  if (parsed.protocol === "https:") return null;
  if (parsed.protocol === "http:" && LOCAL_HOSTS.has(parsed.hostname)) return null;
  return "insecureOrigin";
}

/**
 * The relying-party identity for this instance, or null when passkeys are not
 * possible. Falls back to the configured public URL so an admin who never opens
 * the passkey settings still gets a sensible default.
 */
export async function resolveRpConfig(): Promise<RpConfig | null> {
  const row = await prisma.adminSettings.findFirst({
    select: {
      webauthnRpId: true,
      webauthnOrigin: true,
      publicUrl: true,
      instanceName: true,
    },
  });

  const origin = row?.webauthnOrigin ?? row?.publicUrl ?? null;
  if (passkeyUnavailableReason(origin) !== null) return null;

  const rpId = row?.webauthnRpId ?? new URL(origin!).hostname;
  return {
    rpId,
    origin: new URL(origin!).origin,
    rpName: row?.instanceName ?? "TravStats",
  };
}
```

```prisma
/// One registered passkey. A user may have several — phone, laptop, hardware
/// key — and revoking one must not touch the others.
model WebAuthnCredential {
  id           String    @id @default(uuid())
  userId       String    @map("user_id")
  user         User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  /// Base64url credential ID as returned by the authenticator. Unique across the
  /// instance: the login flow looks a credential up by this alone, before it
  /// knows which user is signing in.
  credentialId String    @unique @map("credential_id")
  publicKey    String    @map("public_key")
  /// Signature counter. A counter that goes backwards means the credential was
  /// cloned; see Task 4 for what we do about it.
  counter      BigInt    @default(0)
  transports   String[]  @default([])
  /// What the user calls it ("MacBook", "Pixel"). Theirs to edit.
  name         String
  /// The RP ID this credential was minted under. Stored so the settings list can
  /// show WHY a key does not work when the instance is reached under another
  /// origin, instead of leaving the user guessing.
  rpId         String    @map("rp_id")
  lastUsedAt   DateTime? @map("last_used_at")
  createdAt    DateTime  @default(now()) @map("created_at")

  @@index([userId])
  @@map("webauthn_credentials")
}
```

```typescript
/**
 * WebAuthn challenges, held in memory.
 *
 * In memory on purpose: a challenge lives for two minutes and is worthless
 * afterwards, so persisting it would add a table, a cleanup job and a migration
 * for no gain. The cost is that a restart mid-ceremony makes the user press the
 * button again — the same cost as a dropped network request.
 *
 * Single-process assumption: this instance runs one Node process per container.
 * If that ever changes, this is the piece that has to move to the database.
 */
export const CHALLENGE_TTL_MS = 2 * 60 * 1000;

interface Entry {
  challenge: string;
  expiresAt: number;
}

const entries = new Map<string, Entry>();

function sweep(): void {
  const now = Date.now();
  for (const [key, entry] of entries) {
    if (entry.expiresAt <= now) entries.delete(key);
  }
}

export function putChallenge(key: string, challenge: string): void {
  sweep();
  entries.set(key, { challenge, expiresAt: Date.now() + CHALLENGE_TTL_MS });
}

/** Read and remove. A challenge answers one ceremony and no more. */
export function takeChallenge(key: string): string | null {
  const entry = entries.get(key);
  entries.delete(key);
  if (!entry || entry.expiresAt <= Date.now()) return null;
  return entry.challenge;
}
```

```typescript
  verifyRegistrationResponse,
  generateAuthenticationOptions,
  verifyAuthenticationResponse,
} from "@simplewebauthn/server";
import { prisma } from "../../db";
import { authenticate, AuthRequest } from "../../middleware/auth";
import { authLimiter } from "../../middleware/rateLimit";
import { AppError } from "../../middleware/errorHandler";
import { generateToken } from "../../utils/jwt";
import { getAuthCookieOptions } from "../auth";
import { resolveRpConfig, passkeyUnavailableReason } from "../../services/webauthn/rpConfig";
import { putChallenge, takeChallenge } from "../../services/webauthn/challengeStore";
import {
  registerVerifySchema,
  loginVerifySchema,
} from "../../schemas/webauthn";
import logger from "../../utils/logger";

const router = Router();

/** Why the UI may not offer passkeys here. Public: the login page asks before
 *  rendering a button, and the answer reveals nothing an attacker cannot see. */
router.get("/availability", async (_req, res: Response, next: NextFunction) => {
  try {
    const row = await prisma.adminSettings.findFirst({
      select: { webauthnOrigin: true, publicUrl: true },
    });
    const reason = passkeyUnavailableReason(row?.webauthnOrigin ?? row?.publicUrl ?? null);
    res.json({ available: reason === null, reason });
  } catch (error) {
    next(error);
  }
});

async function requireRp(): Promise<NonNullable<Awaited<ReturnType<typeof resolveRpConfig>>>> {
  const rp = await resolveRpConfig();
  if (!rp) {
    throw new AppError(
      "Passkeys are not available on this instance — no secure origin is configured",
      409,
    );
  }
  return rp;
}

router.post("/register/options", authenticate, authLimiter, async (req: AuthRequest, res, next) => {
  try {
    const rp = await requireRp();
    const userId = req.userId!;
    const user = await prisma.user.findUnique({
      where: { id: userId },
      select: { username: true },
    });
    if (!user) throw new AppError("User not found", 404);

    const existing = await prisma.webAuthnCredential.findMany({
      where: { userId },
      select: { credentialId: true, transports: true },
    });

    const options = await generateRegistrationOptions({
      rpName: rp.rpName,
      rpID: rp.rpId,
      userName: user.username,
      // Registering the same authenticator twice produces a confusing duplicate
      // in the list; the browser refuses instead when we exclude what we have.
      excludeCredentials: existing.map((entry) => ({
        id: entry.credentialId,
        transports: entry.transports as never,
      })),
      authenticatorSelection: { residentKey: "preferred", userVerification: "preferred" },
    });

    putChallenge(`reg:${userId}`, options.challenge);
    res.json(options);
  } catch (error) {
    next(error);
  }
});

router.post("/register/verify", authenticate, authLimiter, async (req: AuthRequest, res, next) => {
  try {
    const rp = await requireRp();
    const userId = req.userId!;
    const { name, response } = registerVerifySchema.parse(req.body);

    const expectedChallenge = takeChallenge(`reg:${userId}`);
    if (!expectedChallenge) throw new AppError("Registration challenge expired", 400);

    const verification = await verifyRegistrationResponse({
      response: response as never,
      expectedChallenge,
      expectedOrigin: rp.origin,
      expectedRPID: rp.rpId,
    });

    if (!verification.verified || !verification.registrationInfo) {
      throw new AppError("Passkey registration could not be verified", 400);
    }

    const { credential } = verification.registrationInfo;
    const row = await prisma.webAuthnCredential.create({
      data: {
        userId,
        credentialId: credential.id,
        publicKey: Buffer.from(credential.publicKey).toString("base64url"),
        counter: BigInt(credential.counter),
        transports: credential.transports ?? [],
        name,
        rpId: rp.rpId,
      },
    });

    logger.info({ operation: "passkey_registered", userId });
    res.json({ id: row.id, name: row.name });
  } catch (error) {
    next(error);
  }
});

router.post("/login/options", authLimiter, async (req, res, next) => {
  try {
    const rp = await requireRp();
    const options = await generateAuthenticationOptions({
      rpID: rp.rpId,
      userVerification: "preferred",
    });

    // No session yet, so the challenge is keyed to a cookie we set here. It is
    // an anonymous handle, not a credential: holding it proves nothing.
    const handle = crypto.randomBytes(16).toString("hex");
    putChallenge(`login:${handle}`, options.challenge);
    res.cookie("passkey_handle", handle, {
      httpOnly: true,
      sameSite: "strict",
      maxAge: 2 * 60 * 1000,
      path: "/",
    });

    res.json(options);
  } catch (error) {
    next(error);
  }
});

router.post("/login/verify", authLimiter, async (req: AuthRequest, res, next) => {
  try {
    const rp = await requireRp();
    const { response } = loginVerifySchema.parse(req.body);

    const handle = req.cookies?.passkey_handle;
    if (typeof handle !== "string") throw new AppError("No passkey login in progress", 401);
    const expectedChallenge = takeChallenge(`login:${handle}`);
    if (!expectedChallenge) throw new AppError("Passkey challenge expired", 401);

    const credentialId = typeof response.id === "string" ? response.id : null;
    if (!credentialId) throw new AppError("Malformed passkey response", 400);

    const stored = await prisma.webAuthnCredential.findUnique({
      where: { credentialId },
      include: { user: true },
    });
    if (!stored) throw new AppError("Unknown passkey", 401);
    // The password path is not the only place account state has to be honoured.
    // A deactivated user must not get a session through a passkey either — and a
    // user owing a password change must still be sent through that flow.
    if (!stored.user.isActive) throw new AppError("Account is deactivated", 403);
    if (stored.user.mustChangePassword) {
      throw new AppError("Set a new password before signing in with a passkey", 403);
    }

    const verification = await verifyAuthenticationResponse({
      response: response as never,
      expectedChallenge,
      expectedOrigin: rp.origin,
      expectedRPID: rp.rpId,
      credential: {
        id: stored.credentialId,
        publicKey: Buffer.from(stored.publicKey, "base64url"),
        counter: Number(stored.counter),
        transports: stored.transports as never,
      },
    });

    if (!verification.verified) throw new AppError("Passkey could not be verified", 401);

    // A counter that fails to advance is the documented clone signal. Refuse and
    // say so in the log — silently accepting it defeats the point of the counter.
    const newCounter = verification.authenticationInfo.newCounter;
    if (stored.counter > 0n && BigInt(newCounter) <= stored.counter) {
      logger.warn({
        operation: "passkey_counter_regression",
        userId: stored.userId,
        credentialId: stored.credentialId,
      });
      throw new AppError("Passkey could not be verified", 401);
    }

    await prisma.webAuthnCredential.update({
      where: { id: stored.id },
      data: { counter: BigInt(newCounter), lastUsedAt: new Date() },
    });

    res.clearCookie("passkey_handle", { path: "/" });
    res.cookie("auth_token", generateToken(stored.userId), getAuthCookieOptions(req));

    logger.info({ operation: "passkey_login", userId: stored.userId });
    res.json({
      user: {
        id: stored.user.id,
        username: stored.user.username,
        isAdmin: stored.user.isAdmin,
        firstName: stored.user.firstName,
        lastName: stored.user.lastName,
      },
    });
  } catch (error) {
    next(error);
  }
});

router.get("/", authenticate, async (req: AuthRequest, res, next) => {
  try {
    const passkeys = await prisma.webAuthnCredential.findMany({
      where: { userId: req.userId! },
      select: { id: true, name: true, rpId: true, createdAt: true, lastUsedAt: true },
      orderBy: { createdAt: "asc" },
    });
    res.json({ passkeys });
  } catch (error) {
    next(error);
  }
});

router.delete("/:id", authenticate, authLimiter, async (req: AuthRequest, res, next) => {
  try {
    // Scoped by userId, not just id: a foreign key proves the row exists, never
    // that it belongs to the caller.
    const deleted = await prisma.webAuthnCredential.deleteMany({
      where: { id: req.params.id, userId: req.userId! },
    });
    if (deleted.count === 0) throw new AppError("Passkey not found", 404);

    logger.info({ operation: "passkey_deleted", userId: req.userId });
    res.json({ deleted: true });
  } catch (error) {
    next(error);
  }
});

export default router;
```

```tsx
import { useEffect, useState } from "react";
import { startRegistration } from "@simplewebauthn/browser";
import { passkeyApi, type PasskeySummary, type PasskeyAvailability } from "../../lib/api/passkeys";
import { useTranslation } from "../../hooks/useTranslation";

export default function PasskeySection(): JSX.Element {
  const { t } = useTranslation(["settings", "common"]);
  const [availability, setAvailability] = useState<PasskeyAvailability | null>(null);
  const [passkeys, setPasskeys] = useState<PasskeySummary[]>([]);
  const [naming, setNaming] = useState<unknown | null>(null);
  const [name, setName] = useState("");
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    void passkeyApi.availability().then(setAvailability);
    void passkeyApi.list().then(setPasskeys);
  }, []);

  const add = async (): Promise<void> => {
    setError(null);
    try {
      const options = await passkeyApi.registerOptions();
      // v11 takes a wrapper object, not the raw options.
      const response = await startRegistration({ optionsJSON: options as never });
      setNaming(response);
    } catch {
      setError(t("settings:passkeys.cancelled", { defaultValue: "Abgebrochen." }));
    }
  };

  const save = async (): Promise<void> => {
    if (!naming) return;
    await passkeyApi.registerVerify(name.trim(), naming);
    setNaming(null);
    setName("");
    setPasskeys(await passkeyApi.list());
  };

  const remove = async (id: string): Promise<void> => {
    await passkeyApi.remove(id);
    setPasskeys(await passkeyApi.list());
  };

  return (
    <div className="space-y-3">
      <h3 className="text-base font-semibold">{t("settings:passkeys.title")}</h3>

      {/* An unavailable origin gets an explanation, never a button that fails. */}
      {availability && !availability.available && (
        <p className="text-sm" style={{ color: "var(--text-muted)" }}>
          {availability.reason === "insecureOrigin"
            ? t("settings:passkeys.insecureOrigin")
            : t("settings:passkeys.notConfigured")}
        </p>
      )}

      {passkeys.length > 0 && (
        <ul className="space-y-2">
          {passkeys.map((entry) => (
            <li key={entry.id} className="flex items-center justify-between text-sm">
              <span>
                {entry.name}{" "}
                <span className="font-mono text-xs" style={{ color: "var(--text-muted)" }}>
                  {entry.rpId}
                </span>
              </span>
              <button className="btn-secondary text-xs" onClick={() => void remove(entry.id)}>
                {t("settings:passkeys.remove")}
              </button>
            </li>
          ))}
        </ul>
      )}

      {availability?.available && !naming && (
        <button className="btn-primary" onClick={() => void add()}>
          {t("settings:passkeys.add")}
        </button>
      )}

      {naming !== null && (

      {error && (
        <div role="alert" className="text-sm" style={{ color: "var(--danger)" }}>
          {error}
        </div>
      )}
```

## Deviations from this plan, and why (implemented 2026-08-09)

1. **`userVerification: "required"`, not `"preferred"`** — in both ceremonies,
   plus `requireUserVerification: true` on both verify calls. Owner's decision.
   The plan let a passkey replace the password; this implementation also lets it
   satisfy two-factor, and that is only honest if the authenticator actually
   performed a local gesture. Under `"preferred"` a bare-possession assertion
   would be accepted and would bypass a TOTP factor the user switched on.

2. **The passkey route deliberately skips the TOTP challenge.** The plan was
   written before the TOTP feature existed and never mentions
   `twoFactorEnabledAt`; leaving that unaddressed would have made the omission
   look accidental. It is now stated in the handler, in `CLAUDE.md`, and pinned
   by the browser walk-through: with 2FA on, the password path lands on `/2fa`
   and the passkey path does not.

3. **One rpId, a LIST of origins.** The plan's preamble argued for an array and
   its Task 1 code stored a single string. A registration ceremony can only name
   one rpId, while `expectedOrigin` genuinely accepts several — so
   `webauthnRpId` is a string and `webauthnOrigins` is `String[]`. Entries that
   are not secure contexts are dropped rather than trusted, and an rpId that is
   a bare IP disables passkeys instead of minting unusable credentials.

4. **A rename endpoint was added** (`PATCH /auth/passkeys/:id`). The plan listed
   rename in its file-structure table but never implemented it, and the model
   has a user-editable `name`.

5. **`PasskeySection` lives at `components/Settings/`** (capital S), matching the
   real directory; the plan said `components/settings/`.

Verified with Chromium's virtual WebAuthn authenticator
(`hasUserVerification`/`isUserVerified`, resident keys): register, username-less
sign-in, the 2FA asymmetry above, and removal.
